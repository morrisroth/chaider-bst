# חיידר בעל שם טוב — אתר ופאנל ניהול

אתר מוסדי + פאנל ניהול (Node/Express, ללא פריימוורק frontend, ללא בסיס נתונים — אחסון בקבצי JSON).

## התקנה

```bash
npm install
```

צרו קובץ `server/.env` (לא נכלל בגיט) לפי הדוגמה:

```
PORT=4000
JWT_SECRET=<מחרוזת סודית משלכם>
APP_URL=http://localhost:4000
```

`APP_URL` משמש לבניית קישורי החתימה שנשלחים ללקוחות — בפרודקשן יש לשנות לכתובת האתר האמיתית (למשל `https://chaider-bst.co.il`).

## הרצה

```bash
npm run dev     # nodemon, לפיתוח
npm start       # הפעלה רגילה
```

משתמש מנהל ברירת מחדל נוצר אוטומטית באתחול ראשון: `admin` / `admin123` (יש להחליף סיסמה דרך "החלפת סיסמה" בפאנל הניהול).

## בדיקות

```bash
npm test
```

מריץ Vitest על הלוגיקה הקריטית לאבטחה: טוקני חתימה, חישובי תוקף, המרת קואורדינטות PDF, אימות קבצים, והטמעת חתימה ב-PDF.

## מבנה

- `server/` — Express, נתיבי API, אחסון JSON (`server/data/`), קבצים שהועלו (`server/uploads/`, `server/documents/`)
- `admin/` — פאנל ניהול (HTML/CSS/JS ללא build step)
- דפי ציבור בשורש הפרויקט (`index.html`, `gallery.html`, וכו')

---

## מסמכים לחתימה אלקטרונית (PDF E-Signature)

תכונה המאפשרת למנהל להעלות PDF, ליצור קישור חתימה מאובטח אחד, ולשתף אותו עם **כמה אנשים** (למשל כל הורי כיתה) לחתימה בטלפון הנייד — ללא צורך בחשבון מצד החותם.

**קישור אחד = חתימות רבות.** אין "חותם יחיד" למסמך: כל מי שפותח את הקישור, ממלא את שמו, חותם, ומאשר — מתווסף כחתימה נפרדת משלו, עם קובץ PDF חתום נפרד. הקישור ממשיך לקבל חתימות עד שהמנהל מבטל אותו (או שהוא פג תוקף).

**הצד של החותם אינו מוריד כלום.** לאחר השליחה מוצגת רק הודעת אישור — הקובץ החתום זמין להורדה אך ורק למנהל דרך פאנל הניהול.

### איך זה עובד

1. מנהל מעלה PDF ב-`admin/document-new.html`, ממלא כותרת (ותיאור חופשי לא-חובה, כמו "כל הורי כיתה ד'"), ומסמן על תצוגה מקדימה של המסמך היכן תופיע החתימה.
2. המערכת יוצרת טוקן אקראי מאובטח (`crypto.randomBytes(32)`), שומרת רק את ה-hash שלו (SHA-256) במסד הנתונים, ומחזירה קישור בצורת `/sign/<token>` שניתן לשתף עם כמה אנשים.
3. כל חותם פותח את הקישור, קורא את המסמך, ממלא את שמו, חותם באצבע/עכבר, מאשר הצהרת הסכמה, ושולח — ורואה רק הודעת "החתימה נקלטה בהצלחה", ללא קישור הורדה.
4. השרת מטמיע את החתימה (PNG) בתוך עותק חדש ונפרד של ה-PDF המקורי (כל חותם מקבל את עותק משלו), מוסיף בלוק מידע קטן ליד החתימה (שם החותם, זמן UTC, מזהה מסמך) ועמוד תיעוד (audit) מסכם בסוף המסמך, ושומר כרשומת חתימה נפרדת ב-`server/data/document_signatures.json`.
5. המנהל רואה בפאנל הניהול את רשימת כל החתימות שהתקבלו למסמך (שם, תאריך), ויכול להוריד כל PDF חתום בנפרד, לצד הקובץ המקורי.

### אחסון

הקבצים נשמרים על הדיסק המקומי (לא בענן):

- `server/documents/originals/` — קבצי PDF מקוריים שהועלו
- `server/documents/signed/` — קבצי PDF חתומים
- `server/assets/fonts/` — גופן Heebo (TTF) המוטמע במסמכים חתומים לתמיכה בעברית

תיקיות אלו מוחרגות מגיט (`.gitignore`) — יש **לגבות אותן בנפרד** (למשל rsync/backup תקופתי), שכן אין להן עותק במקום אחר.

### אבטחה

- קישורי החתימה מכילים טוקן אקראי בן 256 סיביות; רק ה-hash שלו נשמר בשרת — אי אפשר לשחזר את הקישור מתוך מסד הנתונים.
- קישור פעיל מקבל חתימות מכמה אנשים ללא הגבלה, עד לביטול ידני על ידי המנהל או פקיעת תוקף (אם הוגדרה) — אין "שימוש חד-פעמי" בטוקן עצמו, ובכוונה: זהו קישור משותף לקבוצה, לא סוד אישי לחותם בודד.
- הגבלת קצב (rate limiting) על נתיבי החתימה הציבוריים מונעת ניחוש טוקנים והצפת שליחות.
- תמונת החתימה מאומתת בשרת (magic bytes אמיתיים של PNG, לא רק לפי סיומת), ולא נשמרת בנפרד — היא מוטמעת ישירות בתוך ה-PDF החתום של כל חותם.
- כתיבת חתימה בודדת מוגנת מפני מרוץ בין כתיבות קבצים בו-זמניות (mutex לפי מזהה מסמך) כדי לשמור על תקינות קבצי ה-JSON תחת עומס.
- הקובץ החתום אינו נגיש כלל לחותם עצמו (אין נתיב הורדה ציבורי) — רק למנהל המחובר, דרך פאנל הניהול.

### קישור שאבד

מכיוון שהשרת שומר רק את ה-hash של הטוקן (ולא את הטוקן עצמו), **אין דרך לשחזר קישור חתימה שאבד**. הפתרון: כפתור "קישור חדש" בפאנל הניהול, שמנפיק טוקן חדש ומבטל את הישן.

### מגבלות ידועות

- קבצים "יתומים" (PDF שהועלה אך לא הושלם ליצירת מסמך) אינם נמחקים אוטומטית — יש לנקות ידנית מ-`server/documents/originals/` במידת הצורך.
- אין תמיכה ב-clustering/multi-process — נעילת הכתיבה בעת חתימה פועלת רק בתוך תהליך Node יחיד.
- אחסון קבצים מקומי בלבד — לא מתאים לפריסה serverless (Vercel וכד') ללא שינוי לאחסון בענן.
- אין מנגנון זיהוי חותם (ללא התחברות) — אם אותו אדם פותח את הקישור וחותם פעמיים, ייווצרו שתי רשומות חתימה נפרדות. זהו פשרה מכוונת של המודל (קישור משותף ללא חשבונות), לא תקלה.

### ⚠️ הבהרה משפטית חשובה

מערכת זו מספקת **חתימה אלקטרונית פשוטה** (Simple Electronic Signature) — אימות זהות בסיסי, תיעוד הסכמה, ותיעוד ביקורת (IP, זמן, דפדפן). היא **אינה** מספקת ואינה מתיימרת לספק **חתימה דיגיטלית מאושרת מבוססת תעודה אלקטרונית**, כהגדרתה בחוק חתימה אלקטרונית, תשס"א-2001. לשימושים הדורשים חתימה דיגיטלית מאושרת (חוזים בעלי משמעות משפטית גבוהה, מסמכים רגולטוריים וכד'), יש להיעזר בספק חתימה דיגיטלית מאושר המוכר בישראל.
